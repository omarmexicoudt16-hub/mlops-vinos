# Plantilla del reporte (10–15 páginas)

1. **Portada**: título, tu nombre, materia (Minería de datos 2026B), fecha.
2. **Introducción** (1 pág.): qué es MLOps y qué proyecto hiciste (clasificador de vinos con 4 variables).
3. **Datos y modelos** (1 pág.): dataset `load_wine`, 178 muestras, 3 clases; modelos: Regresión Logística, Random Forest y SVM.
4. **Git y GitHub** (1–2 pág.): qué hacen + capturas (repositorio, `git log`, Pull Request).
5. **DVC** (1 pág.): qué hace + capturas (`dvc add`, archivo `.dvc`, almacenamiento).
6. **MLflow** (2 pág.): runs, comparación, Model Registry con alias `champion`; tabla con tus métricas reales.
7. **Airflow** (1 pág.): DAG de 3 tareas + captura en verde.
8. **FastAPI + página web** (1–2 pág.): formulario, `/docs`, `/health`, error 422.
9. **Docker** (1 pág.): Dockerfile, `docker build`, `docker ps`, app corriendo.
10. **GitHub Actions (CI/CD)** (1–2 pág.): workflow, ejecución ✅, fallo ❌ y corrección, paquete en GHCR.
11. **Monitoreo** (1–2 pág.): reporte de Evidently, variables con drift (alcohol, proline) e interpretación.
12. **Conclusiones** (½ pág.): qué aprendiste y cómo se conectan las herramientas.
13. **Enlace al repositorio de GitHub**.

Para cada herramienta usa este esquema: *qué es → qué hice → captura → resultado*.
